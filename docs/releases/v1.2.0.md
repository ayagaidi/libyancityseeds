# Libya Locations v1.2.0 🇱🇾

**Release date:** 2026-09-07

`v1.2.0` adds **optional geospatial support** for Libyan municipalities while keeping the stable `v1.1.0` base location contract unchanged.

## Map-ready municipality data

This release introduces sourced municipality reference points and partial GeoJSON boundaries for map-based applications.

Current verified coverage:

- **141** municipality rows in the map-point dataset
- **103 / 141 (73.05%)** with published reference points
- **38** intentionally left with `null` coordinates rather than guessed locations
- **10** matched municipality polygon features in the boundary GeoJSON

## Coordinate provenance

Each published point includes:

- `latitude`
- `longitude`
- `coordinate_source`
- `coordinate_source_id`
- `point_type`

Published map references are traceable to OpenStreetMap/Geofabrik, GeoNames, or the available IOM/OCHA operational municipality hub service.

OpenStreetMap-derived coordinates and geometry retain the applicable OpenStreetMap attribution and ODbL requirements.

## Compatibility

There is **no breaking change** to the original municipality/city records. The base contract remains:

```json
{
  "id": 94,
  "slug": "tripoli-center",
  "name_ar": "طرابلس المركز",
  "name_en": "Tripoli Center",
  "type": "municipality"
}
```

Existing applications using `municipalities.json` or `cities.json` can upgrade to `v1.2.0` without adopting map fields.

Applications that need geospatial data opt into the companion map datasets and join them by `id` or `slug`.

## Data-quality principle

This release deliberately publishes incomplete map coverage rather than inventing coordinates. A `null` location means the municipality has not yet been matched confidently enough for publication.

See `docs/MAPS.md` for full coordinate semantics, source notes, attribution, and boundary limitations.
